## Seguimiento

- Estado y asignación de ejecución se actualizan en GitHub; las fichas conservan el ID local y su enlace. No mantener dos estados divergentes.
- Los revisores figuran como propuesta en el cuerpo, no como un mecanismo nativo de aprobación de issues. La revisión efectiva se hace en el PR por alguien distinto de la autoría.
- Los cinco hitos no tienen vencimientos: deben acordarse inicio, entrega oficial y preparación posterior antes de fijarlos.
- No se creó un GitHub Project ni se configuraron automatizaciones de tablero en esta operación.
- Las rutas de documentos referidas por las issues pertenecen al árbol de trabajo; su publicación remota requiere integrar esos cambios. No se hizo commit ni push desde esta operación.
